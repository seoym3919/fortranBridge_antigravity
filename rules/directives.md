# fortranBridge Directives

1. **Directory-First Scope**: Translate entire Fortran directories/codebases by default via `python3 ~/.gemini/config/plugins/fortranbridge/scripts/fortran_bridge_cli.py <dir> --target cpp|python|both --out-dir <out>`. Delegate multi-module porting to `fortran-translator` (`Model: "pro"`) and offset verification to `indexing-auditor` (`Model: "pro"`).
2. **Indexing, Memory & COMMONs**: Convert all 1-based Fortran subscripts to 0-based indexing (`a[i]` for 0-based loops, `a[i - 1]` for 1-based literals). Transpose nested loops in C++ so the innermost loop iterates over the contiguous row-major dimension. Encapsulate `COMMON`/`EQUIVALENCE` blocks into C++ structs/classes or Python `@dataclass` objects.
3. **Closed-Loop Verification**: Compare the original Fortran program's output with the translation using `python3 ~/.gemini/config/plugins/fortranbridge/scripts/translation_verifier.py --ref FORTRAN_OUT --test TRANSLATED_OUT --ref-source ORIGINAL --test-source TRANSLATED --inputs INPUTS`. The pass rule is elementwise `|test - ref| <= atol + rtol*|ref|`, the ULP budget, and the +0/−0 sign bit (float64 default rtol `1e-12`, atol `0`). Claim numerical equivalence only when that verifier exits 0, and quote its exit status. `--self-test` checks the verifier, not a translation. Exit 2 means nothing was compared. Exit 3 means the verdict was withheld. A `--justify` sentence does not release it. Before saying equivalent, `scripts/verification_evidence.py fresh --subject <translated output>` must exit 0.
4. **Complete mathematical port**: Every equation in the original Fortran is translated into the requested target (`python` or `cpp`) and is mathematically identical to the original. Every procedure is unit tested. A regression test covers the whole mathematics. Run `python3 ~/.gemini/config/plugins/fortranbridge/scripts/port_completeness.py --original ORIGINAL --translated TRANSLATED --target python|cpp --unit-tests TESTS --evidence-log .verification/log.jsonl` and claim the port is complete only when it exits 0.
   - An equation is a non-literal assignment (including an assignment inside a one-line `IF`), a non-literal `PARAMETER`, or a condition that contains a binary arithmetic operator. A pure numeric literal is not listed on its own; it still belongs to the original file whose hash the regression binds.
   - Mathematically identical means the latest `translation_verifier` compare record passed (`exit_status` 0, not withheld) and the values are bitwise identical: atol exactly 0 and `max_ulp` exactly 0. Checker version 2 or newer, which also rejects +0 versus −0. The recorded rtol is positive, finite, and no larger than the dtype default from `verification_evidence.limits`. That rtol is not a waiver. A positive `max_ulp`, a nonzero atol, a larger rtol, a justification sentence, and a tolerance approval do not satisfy this rule. If the values differ, investigate why the translated code differs from the original. Do not raise atol, rtol, or `max_ulp` to obtain a pass. Every original file, every translated file, and every `--regression-test` file is a subject whose SHA-256 still matches. The same record also binds the reference output, the translated output, and the inputs.
   - Each procedure other than a `PROGRAM` has a unit test that calls the translated procedure and checks bitwise identity against a numeric literal. The accepted forms are `ulp_distance(got, EXPECTED) == 0` together with `not zero_signbit_differs(got, EXPECTED)`, `compare_vectors(..., atol=0, max_ulp=0)`, and `bit_cast` of the result compared with `bit_cast` of the expected value. Those three functions live in `verification_evidence`. An assertion that only compares the procedure with itself does not count. Plain `==`, `isclose`, `allclose`, `assertAlmostEqual`, `EXPECT_NEAR`, `EXPECT_FLOAT_EQ`, and `abs(a - b) < ...` do not count, because plain equality treats +0 and −0 as the same value. A mention in a comment does not count. If the unit test fails, investigate the translation. Do not widen a tolerance. A `PROGRAM` is emitted as `main`. Other procedures use the translator's Python or C++ name unless `--rename original=translated` says otherwise.
   - Every procedure is reachable from a `PROGRAM` in the original sources, or a `--regression-test` file that calls it is a subject of that same record. The translated procedure is defined, its body is not empty, and it contains no untranslated marker (`NotImplementedError`, `fortranBridge:`, `fortran_untranslated`, `std::logic_error`).
   - Exit 2 means the sources or the log could not be checked. That is not a pass. The checker does not prove symbolic identity of each expression. The identity it enforces is this bitwise regression together with complete, bitwise unit tests. The dtype default in item 3 does not complete a port. If a unit test or the regression differs, investigate the translation.
